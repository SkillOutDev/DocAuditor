# DocAuditor komponentų įgyvendinimo būklė

| Komponento pavadinimas | Įgyvendinimo aplinka / įrankis | Įgyvendinimo laipsnis | Patikrinimo būdas |
|---|---|---|---|
| Dokumentų peržiūros ir įkėlimo komponentas | HTML5, JavaScript, Vite, Tailwind CSS, Django API, `multipart/form-data`, `FileResponse` | **Įgyvendintas / 100 %** – realizuotas PDF, DOC ir DOCX įkėlimas, dokumentų sąrašas, trynimas ir peržiūros langas. | Rankinis failų įkėlimas ir peržiūra. Testai: `backend/api/tests.py`, `backend/api/test_extra.py`. |
| Dokumentų valdymo komponentas | Django, Django REST Framework, PostgreSQL, JavaScript | **Įgyvendintas / 100 %** – veikia įkėlimas, sąrašas, peržiūra, trynimas, savininko patikra, failo dydžio ir formato validacija. | `GET /api/documents/`, `POST /api/documents/`, `DELETE /api/documents/<id>/` ir dokumentų langas. |
| Versijų palyginimo komponentas | Django REST Framework, PostgreSQL, JavaScript | **Įgyvendintas / 100 %** – automatiškai parenkamos seniausia ir naujausia versijos, pasirinkimus galima keisti, palyginamos santraukos, rizikos ir privatumo informacija. | „Palyginti“ funkcija, `POST /api/documents/compare/`, backend ir frontend testai. |
| DI analizės komponentas | Python, Gemini API, `google-genai`, requests, Ollama HTTP API | **Įgyvendintas / 100 %** – veikia dokumento santraukos, rizikų ir privatumo analizė. Gemini naudojamas kaip pagrindinis, o Ollama – kaip atsarginis teikėjas. | `backend/api/analysis.py`, `backend/api/ai.py`, `backend/api/views/analysis.py` ir `backend/api/test_analysis.py`. |
| API nukreipimo komponentas | Django URL routing, Django REST Framework, drf-spectacular, Swagger UI | **Įgyvendintas / 100 %** – realizuoti sveikatos patikros, autentifikavimo, dokumentų, analizės, palyginimo, pokalbio, PDF, OpenAPI ir Swagger maršrutai. | `backend/api/urls.py`, `backend/config/urls.py`, `/api/health/`, `/api/auth/`, `/api/documents/`, `/api/docs/`, `/api/schema/`. |
| Užduočių būsenos koordinatoriaus komponentas | Django `Document.analysis_status` laukas ir analizės API | **Įgyvendintas / 100 %** – realizuotos `pending`, `analyzing`, `completed` ir `failed` būsenos, jos grąžinamos API atsakuose ir rodomos vartotojo sąsajoje. | `backend/api/models.py`, `backend/api/views/analysis.py`, API atsakai ir analizės vartotojo sąsaja. |
| Dokumentų apdorojimo komponentas | Django `FileField`, PostgreSQL metaduomenys, PDF ir DOCX teksto išgavimas, `media` saugykla | **Įgyvendintas / 100 %** – realizuotas failų priėmimas, formato ir dydžio tikrinimas, metaduomenų išsaugojimas, teksto išgavimas ir paruošimas DI analizei. | `backend/api/models.py`, `backend/api/analysis.py`, tinkamų ir netinkamų failų įkėlimo testai. |
| Analizės ir palyginimo komponentas | Django analizės laukai, analizės API, JavaScript, PDF generavimas | **Įgyvendintas / 100 %** – veikia laikinos santraukos generavimas, analizės išsaugojimas, rizikų ir privatumo vertinimas, versijų palyginimas ir PDF santraukos atsisiuntimas. | `backend/api/views/analysis.py`, `backend/api/analysis.py`, `frontend/src/documentspage.js`, backend ir frontend testai. |
| Dokumento susirašinėjimo komponentas | Django REST Framework, Gemini arba Ollama, JavaScript pokalbio langas | **Įgyvendintas / 100 %** – vartotojas gali užduoti klausimus apie pasirinktą dokumentą ir matyti atsakymus peržiūros lange. | „Klausti“ funkcija ir `POST /api/documents/<id>/chat/`. |
| ORM modelių komponentas | Django ORM, PostgreSQL, Django migracijos | **Įgyvendintas / 100 %** – realizuotas `Document` modelis su naudotoju, failu, metaduomenimis, analizės būsenomis, santrauka, rizikų ir privatumo vertinimais bei laiko žymomis. | `backend/api/models.py`, migracijos ir `python manage.py migrate`. |
| „PostgreSQL“ adapterio komponentas | PostgreSQL, Docker Compose, `psycopg[binary]`, Django PostgreSQL backend | **Įgyvendintas / 100 %** – PostgreSQL paleidžiamas per Docker Compose, Django sukonfigūruotas naudoti PostgreSQL, o ryšys valdomas aplinkos kintamaisiais. | `docker-compose.yml`, migracijos ir naudotojų bei dokumentų CRUD operacijos. |
